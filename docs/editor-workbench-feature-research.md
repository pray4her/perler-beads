# 编辑工作台功能与工具调研

> 调研日期：2026-08-02。本文只采用 MDN、W3C/WAI、Aseprite 官方文档及 Piskel 官方源码仓库等一手资料，并结合当前项目代码给出取舍；它不是“把桌面图像软件完整搬进网页”的功能清单。

## 1. 当前能力基线

`PixelEditorWorkspace.tsx` 已有以下能力，后续建议不再重复建设：

- 移动、画笔、橡皮、取色、连续区域填充、直线、描边/实心矩形、矩形框选；
- 选区移动、复制、粘贴、填色、删除、裁切到选区；
- 80 步撤销/重做，工具快捷键，空格平移，鼠标滚轮和双指缩放；
- 画布居中扩展/裁切，透明格、五格主网格、语义缩放、色号显示；
- 当前用色/完整色板、按色相或色号排序、色号与 HEX 搜索；
- 制作底稿、CSV 源数据、展示图预览及标题、字体、透明度、背景色、比例等设置。

真正的差距主要在五处：**工程可恢复性、批量编辑能力、完整键盘与辅助技术支持、大画布数据/渲染架构、保存与发布的区分**。

## 3. P0：先补可靠性、可访问性和性能

### 3.1 原生工程文件 + 自动保存 + 恢复中心

当前编辑器只把预览设置放在 `sessionStorage`，内部剪贴板与 80 步历史也只活在当前组件生命周期；CSV 能重新导入颜色，但不能完整保留色系、预览设置、画布偏好和未来新增的参考层。

建议定义版本化的 `.perler.json` 工程格式，至少包含：`schemaVersion`、网格尺寸、色板系统、以色板索引编码的格子数据、预览设置、显示设置、参考图元数据和更新时间。工程保存与发布导出应明确分开：保存用于继续编辑，PNG/CSV/PDF 用于交付。Aseprite 同样建议用原生格式保存完整信息，再另行导出 PNG/GIF；其恢复机制会定时保存临时数据，并允许恢复上次会话，这证明“保存”和“导出”是两个独立用户任务。[Aseprite：Save](https://www.aseprite.org/docs/save/) · [Aseprite：Files](https://www.aseprite.org/docs/files/) · [Aseprite：Data Recovery](https://www.aseprite.org/docs/data-recovery/)

实现上用 IndexedDB 保存结构化工程、缩略图 Blob 和恢复点；MDN 明确说明 IndexedDB 适合大量结构化数据和文件/Blob，且 API 异步，不会像同步 Web Storage 那样直接占用主线程。[MDN：IndexedDB API](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API) 可在用户明确保存重要工程后尝试 `navigator.storage.persist()`，并显示是否获得持久存储；浏览器仍可能因用户清理、隐私模式或配额而移除数据，因此必须保留“下载工程文件”出口。[MDN：StorageManager](https://developer.mozilla.org/en-US/docs/Web/API/StorageManager) · [MDN：IndexedDB 限制](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Basic_Terminology)

推荐交互：

- 每次提交编辑后防抖自动保存，状态栏显示“保存中… / 已于 14:32 保存 / 保存失败”；
- 首次进入若发现未正常结束的恢复点，提供预览后恢复，不直接覆盖当前内容；
- 保留 3～10 个命名快照和若干自动恢复点，而不是永久保存全部 80 个完整网格；
- 支持“新建副本”“下载工程”“打开工程”“最近项目”，并在 schema 升级时做显式迁移与校验。

### 3.2 完整键盘模型，而不只是字母快捷键

当前工具按钮可 Tab 聚焦，画布也有焦点环，但画布内部没有可移动的键盘焦点格；而 `B/E/I/G/L/R/S/V` 是窗口级单字符快捷键。WCAG 2.2 要求功能可通过键盘操作，并要求单字符快捷键至少满足“可关闭、可重映射、或仅在相关组件获得焦点时生效”之一。[W3C：WCAG 2.2，2.1.1 与 2.1.4](https://www.w3.org/TR/WCAG22/#keyboard)

建议：

- 左侧工具区使用 `role="toolbar"` 和 `aria-orientation="vertical"`，Tab 只进入一次，方向键在工具间移动，Home/End 跳首尾；这是 WAI-ARIA APG 的工具栏键盘模式。[WAI-ARIA APG：Toolbar Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/)
- 画布维护一个“键盘焦点格”：方向键移动，Home/End 到行首尾，Ctrl+Home/End 到画布首尾，Enter/Space 使用当前工具，Shift+方向键扩展选区，Ctrl+A 全选，方向键或数值面板微移选区。该模型与 APG 可编辑网格的方向导航、扩选和全选约定一致。[WAI-ARIA APG：Grid Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)
- 使用 `role="status"`（隐含 `aria-live="polite"`）报告“第 8 行第 12 列，MARD R13，已绘制”“已撤销矩形”等结果；状态更新不抢走焦点。提供简短快捷键帮助和“仅画布聚焦时启用/关闭单键快捷键”设置。[MDN：ARIA status role](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/status_role)
- Canvas 本身对辅助技术不提供像素语义；应在 `<canvas>` 内提供后备内容，并提供“作品摘要/用色统计/当前焦点格”的 DOM 等价信息。MDN 明确建议为 Canvas 提供 fallback text 或子 DOM。[MDN：Canvas 基本用法与无障碍后备内容](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Basic_usage)

### 3.3 所有拖拽都应有点按或数值替代

现有移动、框选和形状主要依赖按住并拖拽。WCAG 2.2 的 2.5.7 要求：除非拖拽本身不可替代，否则同一功能必须提供无需拖拽的单指针操作；只提供键盘替代仍不足以满足这一条。[WAI：Understanding Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)

项目中可低成本补齐：

- 选区面板加入上/下/左/右单格移动按钮和 `ΔX/ΔY` 数值输入；
- 直线、矩形与框选支持“点击起点—点击终点—确认”，拖拽仍作为快捷方式；
- 对称轴和参考图位置同时提供数值输入及“居中”按钮；
- 缩放已经有加减按钮，应再加入“适合画布/适合选区”和可输入百分比；
- 所有小图标按钮至少满足 24×24 CSS px 的目标尺寸或足够间距，重要触控操作优先 44×44。WCAG 2.2 的 AA 最小目标为 24×24，AAA 增强目标为 44×44。[W3C：WCAG 2.2 Target Size](https://www.w3.org/TR/WCAG22/#target-size-minimum)

### 3.4 把卡顿问题拆成输入、数据、渲染三层

当前实现已经把底图和瞬时反馈拆为两个 Canvas，并在笔画中只重绘改变格，这是正确基础；但每次笔画开始仍克隆整个二维对象网格，历史也保存完整网格。最大 500×500 时，长笔画和 80 个快照的对象数量会非常大。

建议按以下顺序优化并用性能测量决定是否进入下一层：

1. **输入合帧**：收集 `pointermove`，每帧只在 `requestAnimationFrame()` 中绘制一次；对支持的浏览器消费 `getCoalescedEvents()`，避免快速笔画漏格。Pointer Events 还提供压力、笔类型和接触面尺寸，为后续手写笔支持留出接口。[MDN：PointerEvent](https://developer.mozilla.org/en-US/docs/Web/API/PointerEvent) · [MDN：requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)
2. **增量历史**：每条命令记录 `{index, before, after}` 的差异，而不是复制完整网格；同一笔画合并成一个历史命令。画布格子改为扁平的 `Uint16Array` 色板索引，透明为保留索引。这与 Aseprite 的 Indexed Color 模型一致：像素引用色板条目，修改条目可统一改变引用像素。[Aseprite：Color Mode](https://www.aseprite.org/docs/color-mode/)
3. **脏矩形/分块缓存**：静态网格、内容和交互覆盖层继续分层；只重绘发生变化的 tile，并缓存透明棋盘格、网格和重复图元。MDN 的 Canvas 优化指南明确建议预渲染重复对象、批处理调用、减少状态切换、只渲染差异。[MDN：Optimizing Canvas](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)
4. **Worker 阈值**：仅当性能数据证明大画布重绘仍阻塞主线程时，把底图合成、缩略图和大图导出迁入 `OffscreenCanvas` Worker；该能力可在 Worker 中绘制，并可通过 `transferControlToOffscreen()` 转移 Canvas 控制权。[MDN：OffscreenCanvasRenderingContext2D](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvasRenderingContext2D)

验收不应只写“感觉流畅”：至少记录 50×50、200×200、500×500 下连续绘制 5 秒的最长帧、P95 输入到呈现时延、一次撤销耗时和历史内存，并把目标设为常规画布接近单帧 16 ms、大画布无 100 ms 以上可感知冻结。

## 4. P1：最值得新增的创作工具

### 4.1 选区布尔运算与像素安全变换

框选完成后应支持“替换、添加、减去、相交”，并补充全选、反选、选择非透明内容、选择同色、重新选择。Aseprite 的选择工具提供加/减/交、全选、反选、重新选择，并允许对选区移动和变换，是成熟像素编辑器的基础工作流。[Aseprite：Selecting](https://www.aseprite.org/docs/selecting/)

变换第一阶段只做不破坏拼豆网格的操作：水平/垂直翻转、90°/180°旋转、方向键单格微移、剪切和就地复制。Aseprite 将翻转、缩放、裁切、修剪和旋转同时用于画布、图像或选区；本项目应先避开任意角度插值，因为拼豆格必须保持离散色号。[Aseprite：Transformations](https://www.aseprite.org/docs/transformations/) 若以后支持任意旋转，应提供像素算法预览和角度吸附，Aseprite 的旋转也提供中心轴和 Shift 角度吸附。[Aseprite：Rotate](https://www.aseprite.org/docs/rotate/)

### 4.2 对称、笔刷和图章

- **水平/垂直对称**：可单独或同时启用，轴线可拖动、数值输入、重置到中心；适合人脸、徽章、花纹和边框。Aseprite 官方对称模式就是可移动水平/垂直轴，绘制会同步作用于两侧。[Aseprite：Symmetry](https://www.aseprite.org/docs/symmetry/)
- **笔刷尺寸/形状**：1、2、3、5 格，方形/圆形（以最终受影响格预览）；橡皮共享尺寸，避免工具设置分裂。
- **从选区建立图章**：保存常用小图案，单击盖印，支持翻转；Aseprite 的官方画笔文档提供圆形、方形、线形及由选区图案建立的自定义画笔。[Aseprite：Brushes](https://aseprite.org/docs/brushes/)
- **形状约束**：Shift 锁定水平、垂直或 45°，Alt 从中心绘制；加入椭圆/圆工具和 1～N 格描边宽度。工具必须在落笔前显示真实受影响格，提交后作为一次历史记录。

压力感应不应作为第一优先级：拼豆格是离散的，压力映射到不透明度没有实际材料含义。若支持手写笔，更合理的映射是“压力越大，笔刷尺寸阶梯变大”，并允许关闭；PointerEvent 的 `pressure` 范围为 0～1。[MDN：PointerEvent.pressure](https://developer.mozilla.org/en-US/docs/Web/API/PointerEvent/pressure)

### 4.3 批量换色与更强的色板

当前按色相/色号排序和搜索已经解决了基础查找，下一步应服务于真实制作：

- “替换颜色”支持全图或当前选区，并在确认前显示 `R13：126 → 0，R12：34 → 160`；
- 填充加入“连续区域/所有同色”开关；“选择同色”可与选区布尔运算组合；
- 最近使用、收藏、前景/备用色、交换两色；右键或长按设为备用色；
- 排序增加饱和度、明度/亮度、使用数量、升序/降序；Aseprite 官方色板提供色相、饱和度、明度、亮度、RGBA 分量排序及升降序，也支持调色板渐变。[Aseprite：Color Bar and Palettes](https://www.aseprite.org/docs/tutorial/color-bar-tutorial/)
- 对拼豆场景加入“缺货替代建议”：限定在当前品牌色板，以可解释的色差排序，并同时展示 HEX、色号、当前用量和替换后的总数量；不得静默自动替换。

### 4.4 参考图层，而不是立即建设通用图层系统

通用图层包含混合模式、合并、跨层选区与导出规则，会显著增加项目复杂度。当前最有价值的是一个受限的“参考图层”：原始图片可见/隐藏、锁定、透明度、位置、缩放，并有原图/网格/叠加/差异四种查看方式。Aseprite 的图层支持命名、可见和锁定；其复制粘贴还区分普通层与参考层，说明“不可误绘的参考内容”是独立需求。[Aseprite：Layers](https://www.aseprite.org/docs/layers/) · [Aseprite：Edit Menu](https://www.aseprite.org/docs/edit-menu/)

只有在用户确实需要分别编辑线稿、阴影和注释时，再升级为 3～8 个有限图层；最终制作底稿必须显式合并可见层，并重新计算用色清单。

### 4.5 拼豆领域的制作检查

以下不是通用 Canvas 规范，而是根据本项目“屏幕编辑最终要转化为实体拼豆”的产品推断，优先级应高于动画、滤镜等通用图像软件功能：

- **底板分块覆盖层**：底板规格可配置，不把某个品牌尺寸写死；显示分界、板编号、跨板连接和导出分页范围。编辑时可吸附到板边，专心模式可按板推进；
- **库存与缺货检查**：用户录入各色库存，工作台实时给出“需要 / 已有 / 缺少”，换色预览同步更新缺口，并可导出采购清单；
- **实体尺寸**：根据珠子直径、间距和底板规格显示预计成品宽高，单位支持毫米/厘米；画布改尺寸时同步显示物理尺寸变化；
- **连接风险提示**：以非阻断警告标出孤立豆、仅单点连接区域、过长单格桥接和疑似误点；允许逐项定位、忽略或加入例外，不能擅自删除，因为孤立元素可能是有意设计；
- **制作模式联动**：当前项目已经有按颜色、连通区域和进度工作的专心模式；工作台应直接预览分区顺序，并把底板编号、库存状态和最新工程版本一并传入，避免编辑与制作形成两套数据。

## 5. P1：保存与导出工作流

建议把顶部操作重新划分为：

- **保存工程**：保留全部可编辑信息；支持下载/打开 `.perler.json`，可选浏览器自动保存；
- **导出成品**：无网格像素 PNG、展示图 PNG，以及“复制图像到系统剪贴板”；Clipboard API 支持异步读写系统剪贴板，但需要安全上下文和权限，应保留内部剪贴板与下载兜底。[MDN：Clipboard API](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard_API)
- **导出制作资料**：当前底稿 + CSV，再增加适合 A4/A3 的分页打印/PDF、页码、拼接重叠区、色号图例和材料清单；导出前检查空画布、超大页数、未映射色号和被裁切内容；
- **导出预设**：整数倍 1×/2×/4×/8×、透明/纯色背景、是否网格/色号、裁切透明边缘、文件名；记住每一种导出的上次设置。Aseprite 的导出也区分源文件与发布格式，并会记住上次导出选项、支持自动缩放。[Aseprite：Exporting](https://www.aseprite.org/docs/exporting)

生成图片应优先用 `canvas.toBlob()` 而不是 `toDataURL()`，避免构造大体积 base64 字符串；浏览器必须支持 PNG，且可在支持时选择 JPEG/WebP。[MDN：HTMLCanvasElement.toBlob](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob) 支持 File System Access API 的浏览器可提供“保存”和“再次保存”到同一文件，其他浏览器继续使用下载链接；该 API 需要 HTTPS 和用户授权，不能成为唯一途径。[MDN：File System API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API)

## 6. P2：导航、历史与专业效率

### 6.1 标尺、小地图和显示偏好

- 顶部/左侧标尺始终按行列显示，主刻度与五格主线一致；鼠标悬停时高亮当前行列；
- 小地图显示画布全貌、当前视口和选区，点击即可跳转；
- 增加“适合画布”“适合选区”“100%”“上次缩放”；
- 网格设置为“自动/始终显示/隐藏”，主网格间隔可选 5/10，色号显示可选自动/始终/隐藏；
- 状态栏增加当前格色号、选区尺寸、选区珠数、总珠数和文档保存状态。

### 6.2 可理解的历史，而不只是两个按钮

保留上一步/下一步，同时提供可折叠历史面板：每条命令有“画笔 24 格”“R13 替换为 R12（126 格）”“画布 60×80 → 70×90”等名称；允许给关键节点命名快照。Aseprite 的官方历史面板同样列出每次动作的状态并允许点击跳转；其线性历史在撤销后执行新动作时会替换后续状态。[Aseprite：Undo History](https://www.aseprite.org/docs/undo-history/) 本项目应在历史条目跳转会清空后续分支前明确提示；工程自动保存只保存少量命名快照和恢复点，不应无界保存全部增量历史。

### 6.3 平铺预览与环绕绘制

对杯垫、边框和重复纹样，可新增水平/垂直/双向平铺预览及环绕绘制。Aseprite 的 Tiled Mode 就用于快速绘制重复图案。[Aseprite：Tiled Mode](https://www.aseprite.org/docs/tiled-mode/) 该模式必须有明显的画布边界和开关提示，避免用户误以为平铺预览部分会被导出。

## 7. 不建议现在优先做的功能

- **完整 Photoshop 式图层、滤镜与任意角度自由变换**：实现和认知成本高，且容易产生不属于拼豆色板的中间色；先做参考层和 90°离散变换。
- **动画时间轴/GIF**：Piskel 的官方定位就是 sprite/animation 编辑器，但本项目核心是单幅拼豆制作，动画不会改善底稿生产。[Piskel 官方仓库](https://github.com/piskelapp/piskel)
- **压力映射透明度、柔边笔刷、抗锯齿**：与一格一颗珠、有限色号的物理约束冲突。
- **协同编辑和云端账户**：在本地工程保存、恢复和格式稳定之前会扩大数据同步与冲突解决范围。
- **一开始就上 WebGL**：当前瓶颈更可能来自全网格对象克隆、历史快照和无节制事件处理；应先测量并完成增量数据与脏区渲染，再决定渲染后端。

## 8. 建议实施顺序与验收

### 里程碑 A：不丢稿、都能操作

1. 工程 schema、IndexedDB 自动保存、下载/打开工程、恢复中心；
2. 工具栏 roving tabindex、画布焦点格、可关闭单键快捷键、aria-live；
3. 拖拽操作的点按/数值替代；
4. `toBlob()` 导出及保存/导出信息架构拆分。

验收：刷新和异常关闭可恢复；只用键盘能完成选色、绘制、框选、移动、撤销、保存；触屏只点按也能完成所有非路径依赖操作。

### 里程碑 B：真正提高精修效率

1. 选区布尔运算、同色/内容选择、翻转/90°旋转/微移；
2. 批量换色、连续/全局填充、最近与收藏色；
3. 对称、笔刷尺寸、自定义图章、形状约束；
4. 参考图层和差异视图；
5. 底板分块、库存缺口、物理尺寸和连接风险检查。

验收：为同一幅对称图案执行“局部选中—批量换色—镜像—移动—撤销”无需逐格返工，且每个操作只形成一条历史记录。

### 里程碑 C：大图和专业交付

1. 扁平色板索引数据、增量历史、rAF 输入合帧、脏区/分块缓存；
2. 200×200 以上按实测决定是否启用 OffscreenCanvas Worker；
3. 标尺/小地图/适合选区、历史面板；
4. 分页打印/PDF、导出预设和平铺模式。

验收：建立固定性能基准；500×500 连续绘制、撤销和导出不出现长时间主线程冻结；大底稿可分页打印且材料清单与画布数据一致。

## 9. 结论

当前工作台已经从“缺少基础工具”进入“需要把编辑器做可靠、做成体系”的阶段。最值得先做的不是继续堆图标，而是：**工程保存恢复、完整键盘模型、非拖拽替代和增量性能架构**。这些基础完成后，选区变换、对称、批量换色和参考图层会带来最直接的创作效率提升；最后再扩展导航、历史、打印和重复图案能力。
