# 编辑器审计与优化说明

## 改造前已有能力

项目已经具备完整的底稿生成主流程：JPG、PNG、GIF 与 CSV 导入，主色和平均色两种像素化模式，切割数量与颜色合并阈值，MARD、COCO、漫漫、盼盼、咪小窝五套色号显示，自定义色板导入导出，杂色排除，一键去背景，颜色统计，图纸与 CSV 下载，PWA 安装，以及按颜色引导制作的专心模式。

旧编辑模式支持单格上色、透明擦除、连通区域擦除、颜色替换、颜色高亮、放大镜局部编辑和单向撤销。这些能力证明底稿数据结构可用，但交互仍是由多个悬浮面板拼接而成的点选工具。

## 主要问题

- 主页面超过 2500 行，转换、下载、工具手势、提示框和页面排版互相耦合。
- 单格编辑会复制整张二维网格，同时更新多个 React 状态。连续绘制无法合并为一次操作，网格越大越容易卡顿。
- 指针移动通过页面状态显示提示信息，会放大高频事件对组件树的影响。
- 画布只有点击，没有连续画笔、视口平移、内容移动、直线、矩形和通用选区模型。
- 历史只有撤销，没有重做；背景处理与普通编辑还使用不同的历史语义。
- 色板只能使用预设顺序，无法由用户选择色相或色号排序。
- 画布尺寸由原图比例决定，编辑后不能增加留白或裁切到内容。
- 展示图与制作底稿混用同一下载概念，无法分别优化展示效果与制作准确性。

## 采用的网页画布实践

React 官方文档说明 ref 的修改立即生效，并且不会像 state 一样触发渲染。因此连续指针轨迹、临时工作网格、拖拽起点和剪贴板使用 ref 保存，只在一次工具操作结束时提交状态。[React: Referencing Values with Refs](https://react.dev/learn/referencing-values-with-refs)

MDN 的 Canvas 优化指南建议按更新频率拆分多层画布、合并绘制调用、减少上下文状态切换，并只绘制发生变化的区域。工作台采用静态图案层和动态选区/形状预览层；画笔移动期间只重绘经过的格子。[MDN: Optimizing canvas](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)

像素画布使用固定内部单格尺寸，缩放交给 CSS，并设置 `image-rendering: pixelated`，避免每个缩放级别重新创建大型位图。[MDN: Crisp pixel art look](https://developer.mozilla.org/en-US/docs/Games/Techniques/Crisp_pixel_art_look)

## 当前实现

- 工具：移动、画笔、橡皮、取色、填充、直线、矩形和框选。
- 矩形：描边与填充模式。
- 选区：移动、复制、粘贴、删除、填色、取消和裁切到选区。
- 视口：空格加拖动或中键拖动进行平移，缩放不改变底稿内容。
- 历史：每次工具操作作为一个撤销/重做单元，最多保留 80 步。
- 画布：输入宽高后从中心扩展或裁切；新增格为留白。
- 色板：图案用色与完整色板切换，色号或 HEX 搜索，按色相或色号排序。
- 展示预览：标题、副标题、字体、字重、字号、文字颜色、透明度、背景色、图案大小、上下位置、三种比例和 PNG 下载。
- 制作底稿：色号体系标题、四边坐标、格内色号、分组网格、用料色卡和总颗数。

## 后续可继续优化

- 当常用网格超过 300×300 时，把颜色映射和大范围填充迁移到 Web Worker。
- 对超大底稿改用分块存储与脏矩形合成，避免历史快照复制完整网格。
- 增加套索选区、旋转、翻转与选区缩放，但保持同一工具操作历史边界。
- 为纯网格算法增加独立测试运行器，覆盖边界裁切、移动越界和透明区域填充。
