# 画布视觉与交互反馈规范

本文记录拼豆编辑工作台的画布视觉语义，避免后续迭代把边框、透明度和交互状态重新混为一谈。

## 设计目标

画布应优先呈现作品颜色，界面结构退居其后。每一种线和底色只表达一个含义：细线表示单格边界，五格主线帮助定位，棋盘格表示透明，暖红轮廓表示正在操作，虚线表示已建立选区，画布外的点阵底板表示不可编辑区域。

## 当前规范

| 对象 | 规则 | 原因 |
| --- | --- | --- |
| 单元格边框 | 逻辑像素 1px；共享边只绘制一次；浅色模式约 13% 深色，深色模式约 14% 浅色 | 避免相邻单元重复描边形成 2px 黑线 |
| 五格主线 | 每 5 格一条，约 30% 对比度 | 低倍缩放仍可定位，但不压过作品颜色 |
| 语义缩放 | 低于 55% 隐藏细网格，只保留五格主线；170% 起显示色号 | 不同缩放层级只展示当下可读的信息 |
| 透明单元格 | 每格 2×2 低对比棋盘；浅色 `#f7f6f2 / #ebe9e2`，深色 `#252522 / #2d2d29` | 透明与白色必须可区分，同时避免高频噪声 |
| 画布边界 | 1px 中等对比外轮廓 + 两层轻阴影；保持直角 | 明确可编辑区域，不用厚重卡片边框误导层级 |
| 画布外部 | 16px 点阵工作台底板，与透明棋盘格采用不同纹理 | 区分“画布里的透明内容”和“画布之外” |
| 画布留白 | 桌面 `32–64px` 自适应，移动端 28px | 给阴影、焦点环和拖拽留出安全空间 |
| 悬停单格 | 暖红 1px 内线 + 反差底线，线宽按缩放反向补偿 | 在任意珠色上都能看清当前落点 |
| 长按拖拽轨迹 | 只描连续区域的外轮廓，暖红前景 + 明暗反差底线；内部不重复描格 | 轨迹看起来是一笔操作，而不是一串黑框 |
| 直线/矩形预览 | 颜色 62% 不透明度 + 连续外轮廓，提交后恢复正常格线 | 同时看清结果颜色与原图位置关系 |
| 选区 | 9–12% 暖红蒙层 + 双层虚线；线宽与虚线节奏保持屏幕尺寸恒定 | 不依赖底图颜色，缩放后仍保持一致视觉重量 |
| 空画布 | 棋盘格上显示“空白画布 / 选择画笔或填充开始创作” | 空状态给出下一步，而不是只留下无意义空白 |
| 键盘焦点 | 2px 暖红焦点环，2–3px 偏移 | 不只依赖颜色或鼠标悬停表达可操作性 |

## 实现约束

- 静态内容层与瞬时反馈层使用独立 Canvas；指针移动不写入 React 状态。
- 画笔和橡皮只局部重绘变更格，完整数据与历史只在 pointerup 时提交。
- 使用 pointer capture 保证指针移出画布后仍能正确结束手势；`pointercancel` 回滚本次瞬时绘制，不提交半截操作。
- Canvas 关闭图像平滑，CSS 使用 `image-rendering: pixelated`。
- 临时轮廓的线宽按 `1 / zoom` 补偿，避免 400% 时变成粗框、35% 时完全消失。
- 任何新交互状态应优先复用现有视觉语义；不要再引入一个相近但含义不清的强调色。

## 后续建议

- 若加入网格显示设置，应提供“自动 / 始终显示 / 隐藏”，默认保持自动语义缩放。
- 若加入选区缩放，只有在真正支持拖动缩放时才显示八个控制点，避免制造错误可供性。
- 若画布超过约 200×200 格，应评估离屏 Canvas、分块缓存或可见区域绘制，而不是继续提高单次全画布重绘频率。
- 若加入笔刷尺寸或压感，轨迹预览仍应呈现最终影响范围，并维持一次手势一次历史记录。
