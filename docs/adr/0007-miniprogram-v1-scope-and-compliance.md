# 小程序 v1 范围：核心闭环 + 专心模式，导出仅图片到相册，个人主体

小程序 v1 功能范围为：创作首页 → 原图整理 → 生成流程 → 编辑工作台 → 保存图纸到相册，外加专心模式；内容页（教程/色号对照/熨烫指南）不搬——它们是 SEO 获客资产，小程序内无搜索流量意义。导出能力只保留图片：`canvasToTempFilePath` 渲染制作底稿与展示图，`wx.saveImageToPhotosAlbum` 落相册；v1 不做 PDF（jspdf 在小程序环境需 polyfill 且中文字体嵌入在 Web 端已是难点），不做复制到剪贴板（小程序剪贴板仅文本）。界面仅中文，但 i18n 字典维持 zh/en 同构并直接共享——「双语路由」「界面文案字典」规则在小程序端为例外：小程序无 URL 级语言隔离，未来加英文只需运行时切换。小程序以**个人主体**注册，v1 不含支持创作入口（捐赠由 Web 站承载）：个人主体不能开通微信支付，且账号与收费系统已确认首期不实现（见 ADR 0008）。类目选工具/图片处理；图片全程本地处理不上传服务器，无需内容安全检测接口；需配置《用户隐私保护指引》并声明相册写入权限用途。

## Considered Options

- **功能全量对等（含内容页）**：内容页在小程序内无 SEO 价值，且个人主体类目可能不允许资讯内容。
- **保留 PDF 导出**：jspdf 小程序适配 + `wx.shareFileMessage` 发聊天可行但风险高，首版图片导出已覆盖制作场景。
- **企业主体一步到位**：为收费预留，但营业执照、认证年审是现实成本，且收费首期不实现；主体演进路径见 ADR 0008。

## Consequences

- 「专心模式」进入后不回编辑界面的规则在小程序端同样成立，进度持久化依赖 ADR 0006 的存储抽象层。
- 小程序端验收依赖根目录 vitest（共享纯逻辑测试）+ miniprogram-automator 核心闭环冒烟，不追求与 Playwright 对等的 e2e 覆盖。
- 个人主体意味着：无微信支付、无 getPhoneNumber、无 web-view。这些限制在 ADR 0008 的收费路线落地前持续生效。
