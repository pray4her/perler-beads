# 账号与收费路线：收费永不解锁功能，openid 静默登录预留，广告 + 材料包电商

账号与收费系统首期均不实现，但路线已锁定，v1 只做架构预留。**收费≠解锁功能**：「支持创作」词条保留并扩展为全产品约束——任何收费形式都不得锁定功能，功能永远全免费。据此收费形式只选两种：**流量主广告**（个人主体可开，需累计独立访客 ≥1000）与**实物电商**（拼豆材料包，与「拼豆爱好者」受众天然契合）；打赏沿用 Web 站现有渠道，付费定制服务不做。广告点位实行创作界面净土制：只允许创作首页底部 Banner 与导出成功后插屏，编辑工作台与专心模式全程无广告。电商入口挂在用料清单上：制作底稿导出页与专心模式完成页（已退出专心状态，不违反净土制）提供「按清单配豆」直达材料包，不设独立商城页、不做色号级购买入口。账号形态定为 **openid 静默登录**（`wx.login` + 后端 code2session，用户无感），只为未来的打赏记录、订单身份、运营标识预留；不做手机号绑定（getPhoneNumber 不对个人主体开放，且数据全本地的产品里属过度采集）。

## Considered Options

- **收费=解锁功能/会员**：与「支持创作」词条直接冲突，会把产品从捐赠驱动改写为付费驱动，且 iOS 虚拟支付在小程序内被微信禁止；已否决。
- **不做账号**：打赏/广告/电商导流都可无账号运行，但未来用户资产（记录、权益）无身份可挂；openid 静默登录成本可控，保留。
- **独立商城页 / 色号级购买入口**：前者与使用场景脱节打开率低，后者污染编辑工作台违反净土制。
- **自建后端服务器**：与微信云开发相比多出备案、运维与证书成本；云开发个人主体即可用，且与小程序同账号体系。

## Consequences（v1 架构预留）

- miniprogram 工程预留 API client seam（首期为 stub），网络请求只允许经此模块，未来接入账号/订单时无侵入。
- 后端方向预定为**微信云开发**（云函数）：承载 code2session、订单与打赏记录，免备案免运维。
- 主体演进路径：v1 个人主体 → 流量主广告 → 材料包电商落地前升级企业主体并开通微信支付；升级是 ADR 0007「个人主体」决策的既定后续，而非反悔。
- 数据边界：后端只承载身份与订单；图片与底稿数据不上传，「本地处理」词条不因账号系统而削弱——未来任何云同步提案都必须先改写该词条。
